# OpenAPI-first REST API with build-time code generation

The DNSCheck service REST API is specified in an OpenAPI document that is the single source of truth. Server JAX-RS interfaces and API models are generated by **Quarkus OpenAPI Generator** during the Maven build. The React TypeScript client and DTO types are generated by **openapi-typescript-codegen** during the frontend build. Generated code is not checked into version control on either side.

The canonical spec file is `dnscheck-service/src/main/resources/openapi.yml`. It is a single OpenAPI 3.1 file with paths grouped by tags (`Auth`, `Zones`, `Reconciliation`, `ZoneView`, etc.). All paths are under `/api/v1/`. Protected endpoints use an OpenAPI `session` security scheme; login and logout remain unauthenticated.

Swagger UI is available in the dev profile only. Production serves the OpenAPI JSON document at a stable URL but does not expose interactive Swagger UI.

Hand-written resource implementations satisfy the generated JAX-RS interfaces and delegate to `dnscheck-core` and service-layer services. The React UI calls the generated TypeScript client. The OpenAPI spec is reviewed in PRs; implementation drift is caught because the generated contracts must be satisfied on both server and client.

The existing hand-written REST resources will be replaced by this workflow as the zone management and auth APIs are built.
